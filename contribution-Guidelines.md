# 🚀 Codeyatri Contributor Guidelines

Welcome to Codeyatri — a growing tech community where builders share, learn, and grow together. If you're submitting a project under the Codeyatri GitHub organization, follow these essential guidelines to ensure quality, collaboration, and community spirit.

## 📁 1. Project Submission Format
Submit your project to the designated repo under the Codeyatri GitHub organization.

Every project must include:
- A proper README.md
- The line "Contributed to Codeyatri" clearly mentioned in the README
- Organized code and files (no zip files or link-only submissions)

## 🧾 2. License (Required)
✅ All projects must include an open-source license — we recommend the MIT License

**Why?**
- It allows others to use, modify, and learn from your code
- Ensures you retain credit and legal protection

**How?**
- Add a LICENSE file in your project root using the MIT template.

## 🧠 3. Code Quality & Review
Projects are manually reviewed before approval. Submissions will be rejected if they:
- Lack a clear and complete README.md
- Do not credit Codeyatri visibly
- Are broken, incomplete, or low-effort
- Contain spam, copied, or irrelevant content

## 🌐 4. Tech Stack & Project Types
All technologies and frameworks are welcome

Accepted project types include:
- Full-stack or mini apps
- Scripts and utilities
- UI/UX concepts
- Open-source libraries or tools

## 🔐 5. Originality
- Only submit original work by you or your team
- AI-generated code is fine if functional and credited
- Plagiarized or copy-pasted content is not accepted

## 👥 6. Contributor Identity
- Projects must be submitted from the contributor's assigned repo within Codeyatri
- Team contributions are allowed — mention all members in the README.md

## 🤝 7. Required Acknowledgment
❗ **Important:**  
All contributors must present their project as a collaboration with Codeyatri, not as an individual or standalone project.

Whether you display it on your portfolio, resume, or social media — you must acknowledge Codeyatri as a collaborative contributor.

## ❌ 8. Rejection & Removal
Submissions may be rejected or removed if:
- Codeyatri is not credited in the README
- Community rules are violated
- Project is incomplete, irrelevant, or non-functional
- Any form of plagiarism is found

## 🧭 9. Community Conduct
- Be respectful, inclusive, and helpful to fellow contributors
- Do not include personal social media links (Instagram, YouTube, LinkedIn, etc.) in the GitHub README.md
- You’re encouraged to share your Codeyatri project link on your own platforms (LinkedIn, portfolio, etc.)

## 🏆 10. Contributor Recognition (Coming Soon)
We’re launching a Contributor Recognition Program featuring:
- Digital contributor badges
- Top contributor shoutouts
- Featured projects on our platform

Stay tuned for announcements!

## ✅ Submission Checklist
- [ ] Added to the assigned Codeyatri repo
- [ ] Clear and complete README.md
- [ ] “Contributed to Codeyatri” is included
- [ ] Project shown as a collaboration with Codeyatri
- [ ] MIT or similar license added
- [ ] Code is working and documented
- [ ] No personal social links in the README
